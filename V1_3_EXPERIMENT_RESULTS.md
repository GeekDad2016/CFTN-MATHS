## What did not pass

The original frozen-GPT language calibration scored 0/1,000 exact tagged
answers. Every generated suffix repeated the instruction-style input and none
contained a valid `<answer>...</answer>` field. This was an interface failure,
not evidence about bridges or specialists: neither had begun training or run
in this stage.

The repair did not lower the 90% semantic threshold. Prompt probes showed that
the original instruction/tag prompt scored 0%, a two-example tagged scaffold
scored only 4/7 registered labels, and the registered key-value completion
interface scored 7/7. A separate 39-label stress probe scored 37/39 (94.87%),
including multi-token and nonce values; the two errors were semantic
associations (`crimson` -> `red`, `Tuesday` -> `Wednesday`). The new sealed
calibration gates first-line semantic accuracy and separately records strict
tag formatting and prompt copying. On the fresh sealed 1,000-example
calibration, semantic accuracy was 100%, valid completion-field rate was 100%,
prompt-copy rate was 0%, and strict XML-tag accuracy was 0% as expected. The
semantic precondition therefore passed; XML formatting is no longer confused
with language competence.

Stage 5 attempt 1 then failed the native string gate under the configured
96-new-token evaluator budget: familiar exact accuracy was 89.35%, task-matched
string cells failed, and required competence coverage was 93.6625%. The math
specialist passed every task-matched cell at 100%. Post-hoc diagnosis found
1,049 familiar string generations at the 96-token ceiling. The completed
`<work>` computation was correct on 1,666/1,667 reverse examples and
1,659/1,666 substitution examples, but 1,043 otherwise-correct outputs lacked
a complete final answer because generation stopped.

This failed evaluation and its pipeline logs are preserved in
`native_specialist_evaluation_attempt1_truncated_96`. The registered repair
does not change model weights, training data, or exact scoring. Evaluator and
pipeline CLIs now record the explicit `full_context_v1` generation policy,
which allows generation until EOS or the tower's existing 256-token context.
The original configured value, effective per-tower budget, policy name,
evaluator hash, and repair reason are written into Stage 5 and Stage 11 reports.
A 64-example probe composed entirely of previously truncated failures recovered
64/64 exact answers, and the full test suite passed 74 tests before relaunch.

The sealed joint evaluator was also corrected before Stage 11 so its
`valid_rate` and competence-supported `valid_rate` use the same registered
first-line completion parser as exact correctness. Native specialist validity
continues to require its own tagged-output contract. A regression test includes
both raw first-line and legacy tagged generations.

## Interpretation and likely causes

Base GPT-2 is a pretrained autocomplete model rather than an instruction-tuned
chat model. Requiring it to obey a novel XML-only instruction made formatting
and prompt-following a hidden prerequisite for a task intended only to verify
no-specialist language competence. The key-value completion repair aligns the
surface interface with the frozen model while still requiring it to select and
emit the correct value rather than merely contain that value somewhere in the
input.
